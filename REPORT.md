## 5. Сравнение DVC и ClearML Dataset

| Критерий | DVC | ClearML Dataset |
|---|---|---|
| Идентификатор версии | Hash содержимого в `.dvc` | ID датасета и номер версии |
| Где хранится метаинформация | В файлах DVC, которые коммитятся в Git | В ClearML |
| Где хранятся файлы | В DVC remote | В хранилище, настроенном для ClearML |
| Создание дочерней версии | Изменить данные и зафиксировать новое состояние в Git/DVC | Создать новый Dataset и указать родительский датасет |
| Переключение версии | Переключить Git-ветку и выполнить `python -m dvc checkout` | Выбрать или скачать нужную версию Dataset |
| Восстановление на чистой машине | Клонировать репозиторий, настроить доступ к remote, выполнить `python -m dvc pull` | Настроить доступ к ClearML и скачать нужную версию |
| Поведение при ветвлении | Версии данных связаны с Git-ветками и коммитами | Можно создавать версии с разными родительскими датасетами |
| Поведение при слиянии | Можно настроить merge driver DVC; итог зависит от указателей на данные | Не является аналогом Git merge; зависимости версий нужно задавать отдельно |
| Связь версии данных с Git | Прямая связь через коммиты, ветки и теги | Связь с Git не обязательна |
| Доступ через UI | Основная работа выполняется командами и файлами в репозитории | Есть веб-интерфейс для просмотра датасетов и их версий |

В этой работе DVC использовался для хранения версий данных рядом с Git-историей, а ClearML — для регистрации версий датасетов и их зависимостей.

## 6. Ответы на контрольные вопросы

### 1. Какой объект однозначно определяет версию данных в DVC?

Файл `.dvc` содержит hash, указывающий на конкретное содержимое данных. В этом проекте в `data.dvc` записан hash каталога `957c42d7c9ecafed014287db892a5932.dir`.

### 2. Почему одного Git-коммита недостаточно без DVC remote?

Git хранит код и указатель DVC, но сами данные находятся отдельно. Без доступа к DVC remote восстановить файлы данных не получится.

### 3. Чем Dataset version отличается от Dataset ID в ClearML?

Dataset ID идентифицирует запись датасета в ClearML, а версия обозначает конкретное состояние данных. Для проверки нужно смотреть и ID, и версию.

### 4. Почему `finalize()` нельзя считать созданием следующей версии?

`finalize()` завершает текущий объект датасета. Для нового состояния нужно создать отдельный Dataset и задать его версию и родительскую зависимость.

### 5. Как доказать, что ClearML version `2.0.0` создана от базы, а не от `1.1.0`?

Нужно проверить список родительских датасетов в ClearML. В проекте у `2.0.0` указан родитель `base`; `1.1.0` не является её родителем.

### 6. Что произойдёт, если после `git switch` не выполнить DVC checkout?

Git переключит файлы, которые отслеживаются Git, но локальные данные могут остаться от предыдущей ветки. `python -m dvc checkout` обновляет их под состояние текущего коммита.

### 7. В каком сценарии удобнее DVC, а в каком ClearML Dataset?

DVC удобен, когда нужно хранить версии данных рядом с кодом, использовать Git-ветки и восстанавливать состояние проекта. ClearML Dataset удобен для регистрации датасетов, просмотра версий и управления зависимостями через интерфейс. В проекте эти инструменты дополняют друг друга.
